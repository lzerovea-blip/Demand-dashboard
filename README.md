# 解决方案需求管理

面向运动健康、穿戴方案团队的离线需求汇总工具。它用于结构化录入需求、按领域合并路标卡片、按半年统计工作量，并按确认后的内置模板输出路标材料。

## 直接启动（macOS）

在项目根目录双击 `启动解决方案需求管理.command`，或直接打开 `release/解决方案需求管理.app`。

不要在浏览器里打开 `src/renderer/index.html`：它是开发源码入口，离开 Electron 桌面环境后无法访问本地数据库和文件能力。

## Windows 版本

GitHub Release 仅提供 64 位 Windows 便携版：

- `Solution-Requirements-Manager-Portable-<版本号>-x64.exe`：便携版，无需安装即可运行。

便携版包含离线数据库、PPT 共创模板和工作区数据包能力，运行时不依赖网络。后续 GitHub Release 只上传 Windows 便携版，不上传安装版、Mac 或 iOS 产物。当前构建未使用商业代码签名证书，Windows 首次运行时可能显示“未知发布者”或 SmartScreen 提示；应在可信来源下载并核对发布文件。

## 当前能力

- 单机 SQLite 数据库，运行时不访问网络。
- 侧栏和内置使用说明显示应用版本、发版时间及制作者。
- 十四类来源：运动/健康各含基础、进阶、高阶，以及行业、全场景、health平台、AI运动、AI健康、AI综合、NMPA送检、CE送检；历史 AI/ai 自动迁移为 AI综合，历史医疗送检自动迁移为 NMPA送检。
- 领域字典分为 L0 与 L1，一个 L0 可关联多个 L1；L0、L1 和产品标签支持双击改名，L1 可按所属 L0 筛选。新建需求先选 L0，再从其子级中选择 L1，路标卡片只显示并按 L1 合并。
- 三类分类：体验优化、平台演进、产品专属；体验优化不匹配产品，平台演进可选一个产品，产品专属必须匹配一个产品。
- 单个上线年月；设备、App、云侧三端工作量均可留空或填写 0，支持整数或小数并自动合计。
- 三端工作量合计为 0 的需求会在需求池标记为“工作量待评估”，便于后续集中补充。
- 每条需求可补充描述和最多 5 张本地图片，图片随离线数据备份保留。
- 需求池支持立即复制完整需求，副本会重新生成需求和图片 ID，并自动递增“副本（1）”序号。
- 人员字典支持姓名、唯一工号、唯一 Microsoft 365 企业账号、单岗位角色和多个负责领域 L1；需求池自动显示规划、产品经理和 SE，并支持三个责任人条件与关键词、来源、分类、月份组合筛选。
- 需求池展示需求标题、领域 L1、来源、上线月份、匹配产品、规划、产品经理、SE 和工作量，并在当前页面宽度内完整排布、不产生横向滚动；领域 L0、适用范围、分类仍保留在需求数据和编辑器中，但不占用列表列宽。
- 需求池标题每 20 个字符自动换行且不限制行数，避免长标题挤压其他字段。
- 按“领域 L1 + 来源 + 上线年月”自动合并卡片，分类不同、L0 不同仍可合并。
- 按时间汇总设备/App/云侧工作量，并用圆饼图呈现三端、七类路标来源、体验优化/平台演进/产品专属占比。
- 汇总分析、路标和导出中心分别保留自己的半年区间，切换页面不会相互覆盖时间选择。
- 固定展示三端投入分组柱状图；可切换设备、App 或云侧，查看所选端中体验优化、平台演进、产品专属三类并列占比柱。
- 运动、健康、行业、全场景、health平台、AI、医疗送检七张路标；页面内“全屏查看”进入七 Tab 沉浸模式，系统窗口全屏只放大普通页面，按 Esc 退出沉浸模式。全屏固定当前路标标题、半年和月份表头，切换 Tab 后从顶部开始浏览。运动与健康使用高阶/进阶/基础三级泳道，AI 路标使用 AI运动/AI健康/AI综合三级泳道，医疗送检路标使用 NMPA送检/CE送检双泳道，其余路标使用单一需求泳道；每张路标独立判断月份占用，空月份固定压缩为 56px。
- 领域卡片标题固定使用领域 L1 标签，不支持手工标题或摘要；点击后默认展开全部需求、产品、总工作量、需求描述和图片，不在详情中重复显示设备/App/云侧拆分；点击图片可在全窗口查看层中按原始比例完整显示，并通过底部缩略图切换同一需求的其他图片。
- 普通路标中，同一泳道、同一月份的多张卡片可直接上下拖拽排序；全屏预览保持只读，排序会同步到 PPT 和数据交接文件。
- 路标轴使用长条卡片，整段文案每行最多 20 字、最多两行，最多取三条需求标题并保留产品标识，完整内容在详情页查看。
- 路标卡片匹配产品时继续显示“涉及产品”；包含体验优化需求时在卡片右侧显示体验优化图标。
- 本地领域 L0 / L1 / 产品 / 人员字典，以及包含需求、描述、原图、卡片编辑、人员责任矩阵和 PPT 白名单的 `.roadmap` 完整数据交接包。
- 支持导出/回导 v6 单 Sheet 协作 Excel，仅在“需求清单”A–N 展示可编辑业务字段；需求 ID、基线与下拉字典保存在 XLSX 内部系统数据中，不暴露到工作表单元格。同 ID 回导保留本机图片，并继续兼容 v2/v3/v4/v5 文件。
- 兼容导入旧版 JSON 备份，支持合并导入或整体替换。
- 内置固定 9 页视觉模板，无需导入外部 PPTX；封面固定，可按需选择汇总页及七张来源路标页，不追加需求详情页或图片页。
- 导出中心在三类导出卡片下方提供独立的全宽 PPT 白名单模块，可从人员字典配置只读/可读可写权限。PPT 使用 Windows 桌面版 PowerPoint 企业 IRM 实施真实账号授权，未授权账号不可读，导出作者保留完全控制，权限固定在导出日起六个日历月到期并显示在封面。
- IRM 环境、企业账号、权限写入或回读任何一步失败都会终止导出，不生成无保护降级文件；macOS 工作台可检查配置界面，但受保护 PPT 只能在 Windows 企业 IRM 环境生成。

## 本地开发

```bash
pnpm install
pnpm dev
```

检查与构建：

```bash
pnpm check
pnpm build
```

生成平台安装包：

```bash
pnpm package:mac
pnpm package:win
```

当前 Windows x64 安装包由 macOS 交叉构建并完成静态资源、类型检查与自动化测试；正式分发前仍建议在 Windows 10/11 实机完成启动、录入、图片、`.roadmap` 导入导出和 PPT 导出的离线验收。

## PPT 模板与数据交接

进入“导出中心”后，可从左到右选择“需求路标”“Excel 表格”或“完整需求包”。需求路标和 Excel 均按导出中心顶部选择的起止半年生成；Excel 用于多人协作编辑和回导，完整需求包用于跨电脑无损交接全部数据与原始图片。

生产 PPT 固定保留封面，并按勾选项依次输出汇总页、运动、健康、行业、全场景、health平台、AI 和医疗送检路标页；常规完整选择为 9 页。若某个“半年 × 泳道”内的独立卡片超过单页容量，系统会保持 8pt 最小字号并自动生成带完整表头的路标续页，避免丢失领域卡片或中止导出。即使所选路标无数据也会输出完整空状态页，所有内容保持原生可编辑，不上传需求或图片。

`.roadmap` 数据包始终导出整个工作区，不受当前筛选和半年区间影响，并携带人员责任矩阵和 PPT 白名单。接收方选择合并前会看到所有记录及字段差异，逐项确认后才可按更新时间合并；也可选择整体替换本机业务数据。

协作 Excel 仅导出所选半年区间内的已有需求用于修改或显式删除，不支持新增需求或维护字典，也不携带原始图片、人员、PPT 白名单或卡片排序。领域 L0/L1 与产品字典作为内部下拉数据随文件保存。多人完成在线编辑后，应用会先校验错误和冲突，并完整列出本机值与导入后值；用户确认全部差异后才能选择保留本机冲突或使用 Excel 版本合并回导。区间外本机数据、人员和白名单不会因未出现在表格中而被删除。

旧版数据中的单一工作量会继续计入总量，并标记为“待拆分”；编辑该需求并分配到设备、App、云侧后，待拆分数自动归零。
