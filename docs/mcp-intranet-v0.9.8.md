# 公司内网模型接入方案（v0.9.8）

## 定位与边界

首版只允许本机 MCP 客户端查询需求池、读取录入参考数据并提出需求新增、字段修改、复制、删除。模型没有直接提交工具。路标匹配、分层支持结论、字典、人员管理、PPT 权限均不开放写入。公司内网模型的客户端名称与配置方式尚未确定，因此本版提供标准 stdio 服务与通用配置示例；协议验收不等于公司模型联调完成。

## 架构

```text
公司内网模型／MCP 客户端
  │ 启动本机便携 EXE --mcp-stdio（标准 JSON-RPC stdin/stdout）
  ▼
MCP 子进程（只负责协议与参数校验，不打开数据库）
  │ 当前用户的临时命名管道／Unix socket + 每次工作台启动随机会话令牌
  ▼
已运行的工作台主进程（唯一数据库写入者）
  │ 查询 → 脱敏结果
  └ 提案 → 待确认页面 → 人工批准 → 重新核验 → 隔离 SQL 副本批量执行 → 一次落盘
```

不开网络端口，也不把数据库交给 MCP 子进程。会话描述文件位于工作台的用户数据目录，Unix 文件与 socket 设为仅当前用户可读写；Windows 使用当前用户配置目录中的随机令牌和随机命名管道。工作台未运行或在“模型接入”中停用时，工具返回明确错误。不要把工作台用户数据目录或会话描述文件共享给其他账号。

`--mcp-stdio` 的 stdout 仅传输 MCP JSON-RPC；诊断信息走 stderr。普通工作台保持图形界面。MCP 设置由用户在“模型接入”页启停；新安装默认关闭，用户启用后跨重启保留。

## 工具

| 工具 | 作用 |
|---|---|
| `list_requirements` | 关键词查询与分页（最多 100 条/页） |
| `get_requirement` | 读取单条需求业务字段 |
| `list_requirement_references` | 读取领域、产品、成员 ID/姓名/角色，供录入选择 |
| `propose_requirement_changes` | 提出 1–25 项新增、修改、复制或删除，返回提案 ID |
| `get_proposal_status` | 查询提案待确认、批准、拒绝、冲突、失败或过期 |

查询结果不包含图片二进制、成员邮箱或 PPT 白名单。图片不会通过 MCP 创建或编辑；复制需求沿用应用现有复制规则。修改仅允许需求录入字段，拒绝路标匹配、分层、字典及人员等字段。新增必须提供三个有效责任人成员 ID；工作量和领域关系按工作台既有规则校验。

工作台预览逐项列出字段修改前后值及删除数量；用户逐批批准或拒绝。批准前复核被操作需求的 `updatedAt`，冲突要求模型重新提出。整批在隔离数据库副本中执行，字段或数据库校验失败时回弃整个副本，不产生部分修改。提案 30 分钟后过期，工作台重启后不保留待处理提案。诊断日志只记类型、数量、结果与失败阶段，不记录正文、图片、账号或白名单。

## 通用客户端配置

先打开 `Solution-Requirements-Manager-Portable-0.9.8-x64.exe`，进入“模型接入”点击“启用 MCP 接入”，然后在支持本机 stdio MCP 的客户端中配置：

```json
{
  "mcpServers": {
    "solution-requirements": {
      "command": "C:\\YourPath\\Solution-Requirements-Manager-Portable-0.9.8-x64.exe",
      "args": ["--mcp-stdio"]
    }
  }
}
```

以上是通用示例，具体字段名取决于公司内网模型客户端。工作台与 MCP 子进程应在**同一 Windows 用户会话**下运行；不要使用服务账号或远程共享目录启动。客户端应在调用工具前完成 MCP 初始化，并在提案后调用 `get_proposal_status` 等待员工审批。

## 落地与验收

1. 在测试电脑上核验便携版正常启动、启用/停用及标准 MCP 握手，停用时不得读取数据。
2. 用隔离需求库测试分页、字典读取、提案预览、批准、拒绝、30 分钟过期及并发冲突；批准后检查需求池、删除记录和分层自动同步。
3. 在公司确定客户端后，将上述命令填入其配置；用公司内网模型执行同样用例，确认身份会话、stdio 启动方式、企业终端防护和审计策略。
4. 未完成第 3 步前，交付结论只写“标准 MCP 协议测试通过”，不写“已连接公司模型”。

本版不提供服务端部署、HTTP/WebSocket MCP、跨设备访问、自动批准或模型修改 PPT 权限。后续如需多人同时修改，应另行设计身份、权限、冲突解决和服务端部署方案。
