# 公司内网模型接入方案（v0.9.10）

## 定位与边界

首版只允许本机 MCP 客户端查询需求池、读取录入参考数据并提出需求新增、字段修改、复制、删除。模型没有直接提交工具。路标匹配、分层支持结论、字典、人员管理、PPT 权限均不开放写入。公司客户端已确认为 OfficeAce，其文档支持本机 stdio 命令；Windows OfficeAce 实机接入需要单独验收。

## 架构

```text
公司内网模型／MCP 客户端
  │ 启动免安装文件夹中的真实程序 EXE --mcp-stdio（标准 JSON-RPC stdin/stdout）
  ▼
MCP 子进程（只负责协议与参数校验，不打开数据库）
  │ 当前用户的临时命名管道／Unix socket + 每次工作台启动随机会话令牌
  ▼
已运行的工作台主进程（唯一数据库写入者）
  │ 查询 → 脱敏结果
  └ 提案 → 待确认页面 → 人工批准 → 重新核验 → 隔离 SQL 副本批量执行 → 一次落盘
```

不开网络端口，也不把数据库交给 MCP 子进程。会话描述文件位于工作台的用户数据目录，Unix 文件与 socket 设为仅当前用户可读写；Windows 使用当前用户配置目录中的随机令牌和随机命名管道。工作台未运行或在“模型接入”中停用时，工具返回明确错误。不要把工作台用户数据目录或会话描述文件共享给其他账号。

`--mcp-stdio` 的 stdout 仅传输 MCP JSON-RPC；诊断信息走 stderr。普通工作台保持图形界面。MCP 设置由用户在“模型接入”页启停；新安装默认关闭，用户启用后跨重启保留。

## 工具

| 工具 | 作用 |
|---|---|
| `list_requirements` | 关键词查询与分页（最多 100 条/页） |
| `get_requirement` | 读取单条需求业务字段 |
| `list_requirement_references` | 读取领域、产品、成员 ID/姓名/角色，供录入选择 |
| `propose_requirement_changes` | 提出 1–25 项新增、修改、复制或删除，返回提案 ID |
| `get_proposal_status` | 查询提案待确认、批准、拒绝、冲突、失败或过期 |

查询结果不包含图片二进制、成员邮箱或 PPT 白名单。图片不会通过 MCP 创建或编辑；复制需求沿用应用现有复制规则。修改仅允许需求录入字段，拒绝路标匹配、分层、字典及人员等字段。新增必须提供三个有效责任人成员 ID；工作量和领域关系按工作台既有规则校验。

工作台预览逐项列出字段修改前后值及删除数量；用户逐批批准或拒绝。批准前复核被操作需求的 `updatedAt`，冲突要求模型重新提出。整批在隔离数据库副本中执行，字段或数据库校验失败时回弃整个副本，不产生部分修改。提案 30 分钟后过期，工作台重启后不保留待处理提案。诊断日志只记类型、数量、结果与失败阶段，不记录正文、图片、账号或白名单。

## 通用客户端配置

先解压 `Solution-Requirements-Manager-MCP-Folder-0.9.10-x64.zip` 到固定位置，保留整个 `win-unpacked` 文件夹及其中的 `resources`、DLL 等文件。双击文件夹内的 `Solution-Requirements-Manager.exe` 打开工作台，进入“模型接入”点击“启用 MCP 接入”。MCP 客户端的命令也指向同一个文件夹内的真实程序 EXE，参数为单独一个 `--mcp-stdio`：

```json
{
  "mcpServers": {
    "solution-requirements": {
      "command": "C:\\YourPath\\win-unpacked\\Solution-Requirements-Manager.exe",
      "args": ["--mcp-stdio"]
    }
  }
}
```

**不要把单文件 `Solution-Requirements-Manager-Portable-0.9.10-x64.exe` 填进 MCP 命令栏**：该文件是 NSIS 解包启动器，只转发参数，不能保证标准输入输出透传。文件夹版无需安装，但不能只拷贝其中的 EXE；工作台与 MCP 子进程应在**同一 Windows 用户会话**下运行，文件夹放在当前用户有权访问的本地磁盘。以上是通用示例，具体字段名取决于公司内网模型客户端。客户端应在调用工具前完成 MCP 初始化，并在提案后调用 `get_proposal_status` 等待员工审批。

## 落地与验收

1. 在 Windows 测试电脑上核验文件夹版正常启动、启用/停用及标准 MCP 握手，停用时不得读取数据。macOS 协议测试和 Windows 文件完整性检查不能替代这一项。
2. 用隔离需求库测试分页、字典读取、提案预览、批准、拒绝、30 分钟过期及并发冲突；批准后检查需求池、删除记录和分层自动同步。
3. 在公司确定客户端后，将上述命令填入其配置；用公司内网模型执行同样用例，确认身份会话、stdio 启动方式、企业终端防护和审计策略。
4. 未完成第 3 步前，交付结论只写“标准 MCP 协议测试通过”，不写“已连接公司模型”。

本版不提供服务端部署、HTTP/WebSocket MCP、跨设备访问、自动批准或模型修改 PPT 权限。后续如需多人同时修改，应另行设计身份、权限、冲突解决和服务端部署方案。

## 连接诊断

“模型接入”页自动显示最后观察到的外部客户端、阶段、活动时间和最近失败；页面可见时每秒刷新。客户端身份来自 MCP 握手声明，不能据此识别背后的具体模型。

- 没有程序启动记录：尚未观察到业务程序进入启动，请结合客户端进程日志检查路径、参数和系统启动拦截。
- 已启动／stdio 就绪但没有初始化：客户端启动了程序，但尚未完成协议初始化。
- 握手完成且工具列表已发送：已建立 MCP 协议连接，尚未代表调用过业务查询。
- 工具调用后桥接失败：检查工作台是否打开、是否启用 MCP，以及是否使用同一系统用户。
- 工作台处理完成且响应已发送：软件已把结果交给标准输出，客户端是否读取仍需客户端日志确认。

日志位于用户数据目录的 `logs/mcp`。工作台与每个 stdio 进程分别写文件，并使用连接编号、请求编号串联查询。每个文件上限 1MB，保留一个 previous 文件以及最近 20 次已结束会话；活动进程不会被清理。只记录诊断元数据，不记录查询关键词、需求正文、完整协议消息、图片、账号或令牌；异常使用安全错误码表示。

页面提供“复制诊断摘要”“打开 MCP 日志目录”“导出诊断日志”。导出 ZIP 只包含 MCP 诊断日志和环境摘要，不包含数据库、会话认证文件或其他业务文件。日志不可写时会显示警告，并在客户端 stderr 提示；stdout 始终只用于 MCP 协议。

“本机连接自检”通过当前真实程序完成握手、工具发现和无匹配结果的只读查询，不写入需求。自检标记为“内部自检”，不计作外部接入；自检通过不代表外部客户端路径或启动方式正确。
